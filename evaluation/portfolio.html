01 문제

RAG는 검색만 잘해서는 안 된다. 문서에 없는 질문에는 "모른다"고 답하는 것도 검색 성능만큼 중요하다. 그런데 검색 점수 threshold 하나에만 의존하는 설계는 이걸 보장하기 어려웠다.

Validation 데이터로 정한 거절 threshold(0.60)는 정답이 있는 질문의 4.3%(3/70)만 잘못 거절할 것으로 예측됐다. 하지만 완전히 분리된 Final Test 셋에 그대로 적용하자 오거절률이 25%(10/40)까지 치솟았다. 같은 corpus, 같은 설정인데도 질문의 표현 방식·키워드 밀도에 따라 검색 점수의 신뢰도가 크게 흔들린다는 뜻이다. 점수 하나짜리 단일 방어선으로는 부족했다.

03 해결 과정

  1. 1
    실제 데이터 수집로스트아크 공식 공지·GM노트 24건 크롤링, 원문 URL·수집일 보존
  2. 2
    평가셋 분리Validation 70문항(튜닝용)과 Final Test 50문항(검증용)을 chunk 단위로 100% 분리
  3. 3
    Retrieval 비교·튜닝Keyword / Semantic / Hybrid 비교, keyword boost 스윕, chunk overlap 실험(결과: 역효과로 기각)
  4. 4
    거절 threshold 결정Validation 데이터로만 threshold를 정하고, Final Test로 일반화 여부를 검증
  5. 5
    Generation 수동 채점25문항의 실제 LLM 답변을 직접 읽고 핵심정보 포함·문서 밖 추측·거절 적절성을 채점

04 결과

Retrieval — Validation과 Final Test 모두에서 Keyword가 Semantic을 크게 앞섰고, Hybrid는 Keyword 대비 뚜렷한 우위를 보이지 못했다.

Keyword Semantic Hybrid

Keyword boost는 0(순수 Semantic)에서 0.05로 올릴 때 Hit@3가 58.6%→80.0%로 가장 크게 뛰었고, 그 이상은 평평하거나 소폭 하락해 boost=0.05로 동결했다. Chunk overlap=100 실험은 81.4%→72.9%로 오히려 악화되어 기각했다 — "경계" 문제보다 "비슷한 문서끼리의 경쟁"이 더 근본적인 원인이었다.

05 한계

  • "비슷한 문서끼리 경쟁" 문제는 미해결 Keyword boost를 더 올려도(0.10~0.30) 개선되지 않았고 chunk overlap도 역효과였다. 카제로스 레이드처럼 여러 단계가 거의 동일한 서술 패턴을 공유하는 도메인에서는 범용 임베딩 + 가벼운 키워드 보정만으로는 근본적인 한계가 있다.
  • 고정 threshold의 질문셋 간 일반화 격차 오거절률이 validation 4.3%에서 final test 25%로 치솟은 원인을 분석했지만, 해결하지는 않았다 — 두 질문셋의 점수 분포 자체가 달랐다는 한계로 기록했다.
  • Final Test는 같은 24개 문서 안에서 분리 완전히 새로운 문서로 구성한 셋은 아니다. Validation이 쓰지 않은 chunk로만 구성했지만, 크롤링을 다시 해서 만든 독립 데이터는 아니다.
